# External knowledge maintenance and scheduling

Read this only for an explicitly requested compiler setup, recurring maintenance
or execution recovery. A downloaded skill, generated prompt, OAuth login or host
"completed" flag does not prove a task was installed or knowledge was compiled.
Use only the bound C0 connection and exact selected authorized space. Discover
actual c0://capabilities, current policy, effective role and Read+Write scopes.
Disabled policy stays disabled; no source, project, permission or schedule changes
are implied. Follow [the common compiler protocol](compiler.md).

## Install and connect

The ChatGPT plugin includes c0-knowledge-compiler. The standalone instance skill
contains the same compiler protocol. A project archive additionally binds its
exact manifest, approved scope and daily/weekly workflow. Install/attach the
appropriate generated archive, connect its existing registered C0 app or canonical
MCP URL, sign in as the intended account, verify spaces_get and inspect actual
capabilities. Never replace a registered app identity merely to refresh guidance.
Older servers without compiler operations retain ordinary research/maintenance;
report the missing capability and stop compiler work without a generic-write bypass.

## ChatGPT task handoff

Use the selected-space prompts on Use with AI. The complete task prompt must carry:

- Exact instance connection, account ID, selected space UUID, compiler skill and,
  when configured, project skill and current manifest version.
- Current enabled policy and required Editor Read+Write access. Recheck at each run;
  permission to write alone does not authorize automatic learning.
- Daily: inspect changed originals, stale dependencies and queued improvements;
  discover bounded current inputs, resume pending verification/uncertain calls,
  assess originals, plan/validate/apply eligible changes, read back exact citations
  and targets, and save actual progress plus a complete/partial maintenance report.
- Weekly: reuse the existing project audit and semantic phase or ordinary-space
  compiler semantic selection/review; rotate a bounded sample, inspect original
  evidence, concept overlap, applicability, contradictions and cross-links; compile
  supported changes and report selected/total counts and unresolved findings.
- The project's IANA timezone, daily_local_time, weekly_day and weekly_local_time;
  preserve schedule.enabled. For ordinary spaces use policy.timezone (default UTC)
  and obtain desired local times before activation. Never guess the browser timezone.
- One logical local occurrence: shift spring gaps by the gap and choose the first
  fall-fold occurrence. Coalesce missed runs to the latest eligible occurrence;
  reconcile incomplete prior work without resetting budgets or claiming missed
  coverage. Compiler daily/weekly keys use the current policy-local date; project
  occurrence identity remains separate. Review changed schedule/manifest bindings.
- Independent C0 run/task/source/target/report readback, observed usage, held
  contradictions, failures and recovery IDs. No raw chat, answer or benchmark labels.

First test the complete daily and weekly prompts manually against an authorized
disposable space. Discover the actual host's scheduling API/interface and durable
skill/connector/authentication capabilities. Inspect existing equivalent tasks;
update the existing project daily/weekly host tasks rather than duplicating them.
Only with explicit installation/activation authority create/update host tasks.
Read saved task IDs, skill/plugin version, prompt, timezone and next occurrences.
Observe a real due run and its saved C0 report; preserve missed/incomplete evidence.
If the host cannot retain the connector, skill or renewable authorization, report
BLOCKED and save this handoff. Do not substitute a deterministic C0 worker.

[Official ChatGPT scheduling guidance](https://learn.chatgpt.com/docs/automations)
describes web tasks using available connected tools/skills and local desktop tasks
requiring the computer/app. Account availability and actual C0 unattended execution
must be verified separately; no task is installed by these instructions.

## External reference runner

The independent c0-ingestion-samples package provides c0-compile outside the C0
server/runtime. Install its actual wheel/archive plus a compatible independently
released Core with the external compiler helpers (already available in0.42).
The selected-page weekly inference alternative needs an actual server capability
from the0.45 producer; older servers leave those reviews pending. M5 producer tests
use explicitly built Core wheels; merging M5 does not publish those artifacts or
change a deployed consumer. Never silently substitute local Core in C0 itself.

The runner supports pinned Codex CLI0.166.0 with an existing dedicated model login,
or an explicit Responses snapshot/API-key adapter, and structured read tool calls and the common Core compiler helpers. Its initial profile creates
source-backed navigation pages; uncertain/contrary, authored/duplicate and queue-only
plans remain reviewable. It never supplies an automatic approval. Large originals
requiring selective context stop with pending work rather than silently truncating.
The adapter's real-provider acceptance and any unavailable host must be reported
explicitly; deterministic mocked responses establish regression behavior only.

Use the repository's [runner setup](https://github.com/Stell0/ns8-czero/tree/main/samples/ingestion/examples/compiler)
for actual installed --help, dry-run, daily, weekly, bootstrap, compile, status,
recover, cron/systemd examples and tests. C0 credentials are private 0600 files in
0700 directories, or systemd LoadCredential files. Codex keeps its own private login outside C0; no provider credential enters a prompt.
Create a dedicated space-scoped
Read+Write key through C0 Account; it acts as its current Editor creator. Never
use an Admin credential, put keys in argv/URLs/prompts/logs or fall back on login.
Revoked/expired/misbound keys stop work. OAuth is supported by the shared client,
but this reference runner deliberately selects API keys; unattended OAuth renewal
must be verified by a host before choosing a different runner.

The private journal saves intent before calls, opaque identities, hashes and usage;
source/model bodies stay transient. Status/recover are read-only inspections. An
uncertain provider call or C0 write stops automatic retry: inspect the actual
saved run/tasks and provider receipt before explicit reconciliation. Do not delete
journals, rename bindings or reset server budgets to bypass uncertainty. Ordinary
space ticks use the existing IANA calendar, a private process lock and server
fences. Configured projects use the existing host workflow's live project lease;
never install a second cron/systemd project scheduler.

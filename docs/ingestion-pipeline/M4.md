# M4 — DOCX, Markdown, plain text and crawler Markdown

This isolated successor depends on M2/M3 acceptance. Default imports and the
released Core lock remain unchanged. The explicit native producer handoff now
publishes every supported format; public session/OAuth handoff remains gated on
a separately reviewed durable authority binding before M9's browser recovery.
No source URL is fetched inside Core and no real corpus is reindexed.

## Contract

Keep one inexpensive unit for small text/DOCX originals. Large DOCX originals
use bounded groups of structural blocks in the existing canonical order: body
paragraphs/tables followed by distinct defined headers and footers. Inventory
and range parsing retain XML/ZIP/unsupported-part guards and merged-cell/link
deduplication. Blank blocks contribute no text, without shifting source indexes.

Large Markdown and text originals use contiguous normalized-character ranges
whose boundaries follow whole paragraphs/blocks. Markdown fences are parsed
before headings; headings inside a fence never start another unit. A large cheap
paragraph or fenced block may remain one unit. Never drop trailing separators,
normalize Unicode or confuse character offsets with publication-part byte offsets.
Preflight freezes the canonical body hash and coordinates outside transactions.

Units read the exact verified original, retain the same parser limits and persist
independently. Assembly verifies manifest coverage, ordered local locations,
every result hash, final canonical hash and existing byte/character/location/chunk
limits. Publish once through the current-content service. Failed-unit retry,
expiry, revocation and supersession retain M2/M3 fencing and recovery semantics.

Crawler output remains externally collected whole-page Markdown and uses this
same format path under explicit native handoff. Existing OAuth collectors and
source-sync receipts/cursors continue working through the default path; this
milestone does not silently turn their approved grants into native authority.
Extraction units never become external multipart publication parts.

Exact unchanged-original uploads keep the existing deduplication contract. A new
queued original generation publishes fresh evidence IDs even when its normalized
body matches the prior body; the legacy path keeps its established narrow reuse.
No existing publication is rewritten merely by enabling a worker or upgrading.

## Required evidence

Compare every M0 original with canonical full-body/hash readback, including DOCX
headers/tables/sections, Unicode, CRLF and fenced Markdown. Use large structured
originals to fail one unit and prove siblings are not reparsed. Cover whitespace
units, ordered/gapped blocks, corrupt manifests/results, chunk/citation offsets,
replacement preservation, role/space denial, external multipart receipts and
actual HTTP/MCP readback. Core independent-package and full/native gates remain.

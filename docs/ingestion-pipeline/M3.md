# M3 — bounded parallel extraction

This candidate follows accepted M2 (`d2fc9a5`). It does not change the default
source extraction path, adopt a released Core dependency or authorize live use.
Acceptance and merges remain sequential; native fixtures are disposable.

## Contract

The native extraction timer is independent of the ordinary serial scheduler and
is active only with the application. Its runner requires explicit opt-in, defaults
to two concurrent isolated parser processes and permits one through four workers.
Each parser retains the existing CPU, memory, output and wall-time limits. The
worker container has a derived memory/swap budget and bounded processes, without
CPU quota flags or host-delegation changes. Stop admission on SIGTERM and finish
or fence in-flight bounded attempts before shutdown. Never share a live parser's
database connection or hold publication locks while parsing.

Claims rotate between runs and cap active leases per document and selected space.
Queue depth and aggregate private-result bytes have hard admission limits. Failed
attempts retain the established three-attempt policy and fencing; successful units
are never reparsed merely because another worker dies. Ordinary jobs retain their
serial advisory lock and existing time/attempt contracts.

Configuration survives configure/update/backup/restore and preserves omitted
settings. Backups stop both timers and workers before the database/source snapshot,
then restore their exact prior activation state. A disabled instance does not
enqueue, parse or backfill existing sources.

Persist bounded queue-wait/run/retry/timeout counters and expose only safe aggregate
worker measurements. Do not label metrics with document IDs, paths, titles, account
IDs or arbitrary exception text. Report actual parser/process memory observations
with their scope; missing cgroup measurements remain unavailable.

The pool shares one existing bounded seven-connection Core engine, with at most
four parser coordinators. Native limits are 1 GiB RAM and 2 GiB combined RAM/swap
per configured worker, with a 256-process ceiling. Each parser still has its own
512 MiB address-space and 25-second parent deadline. No CPU quota is added.
Native two/four-worker fixtures grade actual cgroup memory/swap/process limits,
observed per-parser peak RSS and, where available, cgroup peak memory. A missing
cgroup peak remains null and is never presented as a measured whole-pool peak.
Timing counters cover attempts after schema 0026, without inventing old durations.

## Required evidence

Run real concurrent parsers with another document and an ordinary health job;
verify no duplicate claim/publication, starvation or space crossover. Kill and
restart a pool, reject zombie completion and recover only expired units. Exercise
backpressure, shutdown, resource settings, omitted-setting preservation and actual
native configure/update/restart/backup/restore. Measure one/two/four-worker modes
without promising a multiplier. Core packaging, M0–M2 and full/native checks remain
required before acceptance.

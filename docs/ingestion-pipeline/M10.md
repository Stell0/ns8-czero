# M10 — measurement and guarded rollout candidate

M10 acceptance depends on accepted M1–M9. This isolated candidate prepares
reproducible extraction and retrieval measurements, destructive disposable
recovery, genuine-predecessor native upgrade/reindex proof and operator rollback
instructions. It does not enable a production default or change an installation.

## Extraction measurements

Run `scripts/benchmark-ingestion.py` with an explicit loopback PostgreSQL
administrator URL in `CZERO_EVAL_DATABASE_URL` and a new private `--output`.
The runner creates/drops only its own randomly named databases; measurement
children refuse every other database name. Every input is checked against the
frozen M0 original/expected-text manifest before execution. No model is called.

Compare the legacy whole-document handler with one/two/four queued workers,
each with disabled result caching and with a prewarmed current owner in the same
space. Rotate arm order between repetitions. Default five repetitions report
median and nearest-rank P95; a one-pass `--smoke` result is explicitly exploratory.
"Cold" means disabled output reuse, not flushed operating-system/disk caches.
Continuous bounded one-shot drains exclude the native timer's wake-up delay.

Record upload, manifest/preflight, extraction/publication and verified end-to-end
time, CPU seconds, 50 ms sampled process-tree RSS, explicitly labelled lifetime
RSS, SQL statement count/aggregate elapsed time, database/table size and raw
asynchronous PostgreSQL block/tuple/IO counters. These are observations, not a
fabricated CPU quota, exact memory peak, synchronous IO attribution or billing
estimate. Local OCR reports no provider charge; unavailable cost remains null.
Whole text/hash, character count, source locations and every search-chunk span
must match the independent canonical originals. Tiny inputs remain in the matrix.

## Retrieval comparison

`scripts/benchmark-selective-context.py --prepare` freezes source/corpus/rubric/
driver hashes, four questions, matched interfaces and bounded resources without
calling a model or database. `--fixture-check` exercises real Reader-scoped MCP
and independent database/evidence grading with deterministic parent-side outputs;
it explicitly cannot establish model quality.

The separately authorized model comparison reuses the existing isolated Codex
app-server driver, with actual read-only tools and one exact document generation
for both arms. Each episode gets a fresh model workspace/process and Reader
grant/client. Parent-side guards reject writes and other spaces. Original body,
labels, grader and other questions stay outside the agent workspace. Actual
selected text must be observed and exact cited chunks must cover every required
span. Correct prose without observed evidence earns no evidence credit. Record
actual calls, context bytes, reported tokens, latency and all failures. Prose
entailment still needs independent review; lexical labels alone cannot accept it.
No ChatGPT installation or native Codex-discovery acceptance is implied.

Default comparison: eight `gpt-6-astra`/high turns through codex-cli 0.166.0,
each bounded to eight calls, 180 seconds, 262144 context bytes and 16384 observed
tokens. Token limits are checked from reported usage, not a billing quote.
Model execution requires the explicit authorization in c0-evaluate-tools.

## Recovery and upgrade

`scripts/verify-ingestion-restart.py` refuses containers without its disposable
name/label, reviewed immutable PostgreSQL image and exact loopback port binding.
It targets the inspected immutable container ID. A separate database container
keeps restart/fault injection away from all ordinary acceptance databases.
The proof interrupts an uncommitted result, restarts PostgreSQL, verifies rollback
and a previously successful unit, expires only the interrupted synthetic lease,
rejects its stale completion, and starts a fresh actual worker process. It checks
one complete current publication, exact body/locations/original and cleared staging.

The existing Debian native update retains the genuine installed `31b0c85` image
trio and its seeded source/identity/files/settings/schedule proof. No documentation
image is substituted as a predecessor. At the end of native acceptance, explicit
retained-original reindex is exercised on the restored two/four-worker OCR
fixtures: same complete body/original, warm current reuse, fresh exact IDs, old
citations 410, one current generation and real retired-original GC. Only the
fixture's retired cleanup intent is advanced; production cleanup delay stays
unchanged. Artifact grading requires both reindex markers. Earlier tests keep
their strict corpus/indexing assertions and failed evidence remains preserved.

See [rollout and rollback](ROLLOUT.md). Producer proof, immutable Core publication,
released-consumer pin/lock/image proof and disposable opt-in pilot are separate
gates. No stable module release or live deployment is part of this authorization.

## Development checkpoint

Seven measurement/grader controls, 63 existing/new strict evidence controls and
two actual two/four-worker reindex fixtures pass. The MCP fixture control covers
all eight question/interface pairs, with exact original evidence and no mutations.
The earlier 280-background-record development corpus observes 96878 versus
17775 serialized result bytes at two calls per fixture;
these deterministic outputs are not model-quality or measured answer claims.
Before any model turn, the final corpus uses 100 unrelated background records
to fit the declared observed-token ceiling; the earlier corpus/report stays
preserved. The rubric/questions and safety/evidence requirements are unchanged.
The first extraction smoke checks whole, one/four-worker cold and two-worker warm
plain text with exact body/locations/spans. Full repeated measurements, full
failure/native/consumer gates and actual model results remain unaccepted here.

The actual independent PostgreSQL restart proof passes rollback, preserved
success, stale-token rejection, fresh worker process, exact original/body/
locations, single publication and staging cleanup. Only page 2 has two attempts;
the other four retain one. Its original cleanup failure exposed a stale
administrator connection after restart; the shared disposable-database helper
now pre-pings before dropping its owned database, and the successful repeat
records cleanup completion. Earlier failed observations are retained.

The operator explicitly chose to keep model-quality acceptance open on
2026-11-03. No model turns are run for this task. Continue deterministic,
protocol, recovery, native and released-consumer work; do not count fixture
outputs as a substitute or use this candidate to change the production default.

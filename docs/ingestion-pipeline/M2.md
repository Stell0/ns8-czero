# M2 — PDF units and complete publication

Implementation and acceptance are separate. M2 depends on accepted M1 and keeps
the queued path explicitly opt-in. It introduces no automatic reindex, consumer
Core dependency change, native worker pool or production deployment.

## Execution and publication contract

PDF preflight reads the verified original in an isolated bounded process outside
a database transaction. It checks encryption, page and decoded-stream limits and
returns a bounded page inventory. Enqueue rechecks persisted Editor authority,
source identity, original hash, processing generation and unchanged queued state
before atomically storing one unit per page and handing off the legacy job.
The manifest freezes the ordered page boundaries and extractor profile. Each
unit fingerprint binds that manifest, ordinal and locator.

Each page parser opens the exact retained original, with the existing file,
process, memory, CPU, wall-time and output limits. A readable page contributes
its normalized text unchanged. A verified blank page contributes no text or
location. Image-only or ambiguously graphical empty pages fail explicitly with
`unsupported_scan`; OCR remains a later opt-in milestone. No page result is a
public document or source-sync publication part.

Assembly reads a bounded complete snapshot, then releases its database connection
before verifying result hashes, ordered page coverage, canonical separators,
locations, aggregate limits and chunk slices. Publication reacquires the content
lock and authority lock in the existing order, rechecks the generation, actor,
manifest, result identities and source state, and commits the complete document,
chunks and durable ready marker together through existing publication services.
Competing assemblers reconcile against that marker. Missing, corrupt, expired or
superseded results never publish. Failed replacements retain the previous complete
generation. External multipart sources retain their existing parent commit gate.

An authorized operator may retry only failed units with an expected run revision
and idempotency key while the original and successful sibling results remain
within their original staging lifetime. The operation resets the bounded automatic
attempt budget, preserves monotonic lease fences and lifetime attempt counts, and
never rearms successful units. Replayed retry acknowledgements recheck current
authority and run identity. Expiry returns `staging_expired`; it never silently
falls back to a whole-document retry or claims retained page outputs exist.

For native operator recovery in an explicit producer environment, set
`CZERO_EXTRACTION_UNITS=1` and invoke `python -m czero_app.extraction_admin --run
<run-uuid> --space <space-uuid> --expected-revision <revision> --idempotency-key
<unique-key>`. It uses the already persisted configured owner, does not contact
the identity provider, and returns only the saved retry acknowledgement.

After expiry, failed-unit retry is unavailable. An explicit full rerun of an
unpublished candidate uses the existing `SourceService.retry` at its expected
processing generation, then `ExtractionQueue.enqueue` for the returned generation.
This discards all old unit outputs and parses the whole original again. A
concurrent legacy worker may win the handoff; a conflict is explicit and must be
reconciled from source status. A published version cannot use this operation;
deliberate published-source reindex belongs to M9 and needs fresh evidence IDs.

M2 bounds staging to 24 hours from each run's creation, without extension by
automatic or failed-unit retry. It replaces M1's additional initial-upload-age
ceiling so an explicitly requested new processing generation can use a still
retained original. Ordinary abandoned-version maintenance excludes live unexpired
runs, including retry-eligible failed runs. After expiry, existing cleanup may
retire an unpublished original; a retired version requires a new upload.

## Required evidence

Use the labelled 100-page M0 original and disposable PostgreSQL. Fail pages 37
and 72, kill a real worker holding page 72, reclaim its expired lease, reject its
late result and recover without parsing the 98 successful pages again. Verify one
complete publication, baseline body hash/order, exact citations and duplicate
completion recovery. Also cover blank/scanned/corrupt/over-limit originals,
result corruption, failed replacement, role revocation, protected-space denial,
source replacement/deletion, expiry and external multipart readback. Run existing
M0/M1, source, current-content, HTTP/MCP and independent package regressions.
Record actual results here; test definitions or started CI are not acceptance.

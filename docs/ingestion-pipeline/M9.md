# M9 — progress, diagnostics and controlled recovery

This candidate adds browser-only progress and recovery surfaces on reusable
Core operations. Schema 0030 adds only a default-false explicit reindex intent;
upgrade queues no work and changes no current bodies, chunks or citations.
Acceptance and merges remain sequential after the preceding milestones.

Knowledge Explorer reads selected-space source progress without unit bodies or
Admin queries. It distinguishes queued, processing, retrying, failed, cancelled
and ready, reports completed/total units and preserves the previous complete
document during a pending replacement. An initial incomplete import has no body.
Exact snapshot readers never switch themselves to a newer generation.

Background Work has a selected-space picker and bounded run/unit pages (at most
100 items; the browser uses 20). Only current Admin/c0:admin authority can read
unit diagnostics: ordinal/page range, safe error, attempts, UTC retry timestamp,
observed attempt duration and closed parser revision metadata. Queries never
select result bodies, original paths, filenames, credentials or lease tokens.
Every lookup authorizes the selected space first; there is no Shared fallback.

Editor/c0:write recovery uses existing CSRF and current Core authorization:

- Retry failed units requires the current run revision and an actor-scoped
  idempotency key, keeps successful results and retains the original submitting
  account/space authority. It does not create a new durable handoff.
- Cancel checks the expected revision, fences leases and erases private results.
  Repeated cancellation is idempotent; a published run cannot be cancelled.
- Full restart uses the existing generation-bound source retry, processing all
  units again after cancellation or staging expiry. The ordinary worker remains
  the default for this new attempt.
- Explicit reindex in Source tools requires a retained verified original and
  current source revision/idempotency key. It stages a new complete generation,
  keeps current evidence until publication, then expires old exact citations.
  Identical text does not suppress this explicitly requested publication.
  Managed source-sync parts/parents must use their own complete publication
  workflow. Missing originals produce an explicit error, never reconstructed
  text disguised as original bytes.

The M1/M4 public enqueue gate remains: session/OAuth callers cannot turn an
upload into a native job. Browser recovery of an existing native producer run
rechecks both the operator and the original run account/space; it never replaces
that account with the operator. Existing public ingestion, grants, scopes,
source-sync receipts and released-Core consumers retain their original path.
Routes are capability-gated when older released Core lacks this feature.

Browser controllers use DOM text, captured revisions, retained keys for uncertain
replies, selected-space URLs, access-loss clearing and response-generation guards.
Ordinary readers load no mutation controller or Admin diagnostics. The existing
native HTML stack, theme tokens, selected-space and subpage skip-link contracts
are preserved. New UI wording follows Nebula writing/glossary guidance.

# M2 — guarded external knowledge compiler

Implementation starts from original main `69d6115e3a5778d4608b8f2460e75a9a07a49210`,
after accepted M1 and released Core 0.39 adoption. Read [CONTRACTS](CONTRACTS.md),
[M1](M1.md) and [the milestone plan](PLAN.md) together. This milestone authorizes
no Core publication, consumer lock adoption, deployment, policy enablement, live
knowledge changes, discovery sweep, retrieval hook or scheduler.

## Refined interface and scope

Core producer 0.40 adds no tables or migration: schema 0033 already has publication,
dependency, compiled-generation, outcome/event and pending-verification fields.
Existing ordinary knowledge APIs remain independently authorized and compatible.
The reference app conditionally installs four new operations only with M2 Core:
`compilation_target_bindings_get` (read-only POST `/target-bindings`),
`compilation_plan_validate` (POST `/plans/validate`), `compilation_apply` (POST
`/apply`) and `compilation_verify` (POST `/verify`), all below `/api/v1/compilation`.
Every call requires explicit space. The binding read needs Reader+Read and works
without enabling policy. The three publication operations require current
Read+Write/Editor, enabled policy and live
actor/owner/fence. Read-only dry-run needs this workflow authority but persists
neither knowledge nor coordinator state. A validation result never grants authority.

Tool-only agents obtain the stable new-page slug from tasks_get.managed_slug and
current record hashes/ownership from target_bindings_get. This bounded metadata
read is finite and space-authorized; agents must still read actual content and
compare current identities. Neither local code execution nor invented hashes are
required. Optional Python helpers retain independent hash projections.

The closed v1 envelope in C4 is retained. Each target binding identifies one
content operation by its index, canonical key, kind, current ID/revision/content
identity (null IDs and revision zero for creates), managed ownership declaration
and 1–32 exact support passages. Passages contain chunk ID, absolute document
start/end offsets and exact quote. They are transient input, never retained in
coordinator rows/receipts/events. The server validates original slices and hashes.
Source bindings must exactly equal the reserved task's current M1 bindings.
Dedup decisions bind actual current candidate identities to a fixed comparison
and rationale code; matching slugs/aliases win, ambiguous comparisons require
review. Semantic equivalence remains an attributed external judgment.

One task publishes one primary Wiki concept, plus bounded supporting graph
records in the expanded profile. Multiple concepts use separate tasks, preserving
M1's page budget. The default `sourced-navigation-v1` permits Wiki upsert and
source-bound, unverified verification annotations. Explicit Admin selection of
`sourced-knowledge-v1` and its target allowlist additionally permits entity
create/update/alias/link, sourced claim create/update, and relation create/update.
No object/schema/source/permission/job/schedule/delete/archive/unlink operations.
A content update requires exact expected revisions. Authored targets never become
automatically managed merely because metadata says so: ownership requires the
retained compiler dependency hash to equal the actual current record hash.
Authored edits and uncertain/contradictory plans need exact-plan review. Approving
one authored edit does not transfer ownership: its dependency ownership hash stays
null and subsequent edits still require review. Proposals cannot overwrite actual
published support with merely observed support.

Validation takes `{lease, expected_revision, plan}`; the revision is the run CAS.
It performs trusted bundle dispatch in a rolled-back savepoint, exercising actual
per-record checks, result references, alias ownership and atomic behavior. It
returns canonical plan/identity hashes, eligibility/review outcome and normalized
metadata bindings, without retaining proposed text. Unsupported assertions must
be deferred and cannot be made publishable by approval. Empty plans use checked
M1 no-change checkpoints. No model/provider is invoked by Core.

Apply adds `plan_hash` and optional `approval: {plan_hash, reference}`. Approval is
an Editor's explicit exact-plan decision; its reference is hashed in audit state.
It is not evidence of semantic truth or an independent human identity. Queue-only,
authored edits, review classifications and graph-profile changes require it.
The skill must have actual user/operator approval before supplying it; enabling
learning alone is insufficient for review-held changes. Planning a task already
held by M1 uses explicit manual `review_task_ids` plus
`review_authorization_ref` in run claim. Other origins never select held tasks;
this permits review preparation, not publication approval or hold removal by a
reason rename.

Apply rechecks all authority, policy, sources, targets, quotas, model-call state
and fence under the existing object → knowledge → authority → current-content
lock order, then commits bundle, metadata-only outcomes/dependencies and source
partial markers in one transaction. Each target depends only on the logical originals and exact passages declared
for that target, including every retained claim evidence link. Publication replaces
older dependency edges atomically; previous task/source/event identities
remain metadata, while authored knowledge is preserved. Dropped support leaves its
source assessment partial for later reconsideration. A task becomes
`applied_pending_verify`;
last successfully compiled fields remain unchanged until verification. Deferred or
unread source context retains partial source state and cannot advance successful
source coverage. The external agent reports unread originals explicitly; structural
checks cannot prove that a model actually examined all supplied context. Replays
revalidate the saved actual outputs, not the now-retired pre-update target.
A create-only topic resolves its retained current page on changed-source input,
without turning a title variant into another concept. Explicit reconciliation can
reopen the same task under review with consumed attempts intact; publication
outcomes are selected by monotonic task revision, not wall-clock/UUID order.
Source generations select the actual predecessor-chain head through the existing
predecessor index; equal timestamps and descending UUIDs cannot fork retry lineage.
Each exact request replays only its own still-current outcome. A create-only topic
retains its task/topic mapping after publication; cosmetic
proposal variants do not create a second concept. Stable slug uniqueness and
actual alias ownership remain final race controls.

Verify takes lease/run/task CAS, policy revision, plan hash, observed current
record bindings and original source bindings. The agent must read all targets,
annotations and citations first. Core rechecks those exact observations against
current SQL records and saved apply outcome. Publication outcomes retain typed read locators, classification and metadata-only deferred findings.
It records metadata-only proof,
sets dependencies current and advances successfully compiled source identities;
only then is the task `succeeded`. This proves persisted readback, not entailment.
An intervening edit, expired original or lost fence prevents completion. Pending
verification is resumable under a reclaimed fence without repeating publication.
Model reservations/unknown usage are never refunded or converted into truth.

## Reuse and delivery

Extract only trusted connection-bound bundle composition and small pure passage/
record-binding validators. The experimental evaluator keeps its separate benchmark
routing and private local ledger. Production reasoning lives in the portable
`c0-knowledge-compiler` skill and its installed reference, with capability discovery,
plan/apply/verify/recovery steps and original-only support. Generic plugin, instance
skill and project packages include the reference; older Core tools do not advertise
the workflow. Registered app identity/scopes remain unchanged. Runtime COPY,
closed audit inventory, native downloaded archives and evaluation inputs stay
synchronized. No new CLI/model adapter or scheduling instructions are introduced
here; those belong to M5.

## Executed local evidence

Against original main `69d6115` and the reviewed M2 source, actual disposable
PostgreSQL checks pass: 58 accepted M0/M1 controls; 161 focused compiler,
REST/MCP, multipart/migration and generated-archive cases; and 68 broader protocol,
recovery and compatibility cases. The current and legacy MCP SDKs execute
three distinct concepts, aliases, relationships and contrary sourced claims from
frozen originals. Initial construction does not receive evaluation questions.

All 1,616 fast Python unit cases pass (one upstream Authlib deprecation warning).
All eight independent distribution checks pass, including deterministic wheel/
source rebuilds, clean external installs, fresh/repeated schema0033 migration and
actual guarded compilation in both installed artifacts. A separate clean dump/
restore preserves the six coordinator tables, rejects the old database fence and
verifies a pending saved publication without repeating it. All 27 Node controller
checks, Go schema checks, shell syntax, 21 Robot dry runs, skill validation and
382 maintained documentation links pass.

Earlier failed runs are retained privately. They exposed a missing source-template
link, outdated additive tool inventory and incomplete review declaration in the
installed fixture. A password-masked disposable database URL and local read-only
build mount were corrected without weakening their assertions. Source changes
and authored reconciliation retain separate frozen candidates and evidence. A final
three-generation regression reproduces timestamp/UUID-dependent predecessor
selection; using the existing predecessor chain fixes it. All 76 affected
coordinator/compiler, multipart/migration and real MCP cases pass after that fix.

A subsequent 135-case selection passes after adding the read-only target binding
operation, including a tool-only apply/readback path in both MCP modes, disabled
policy reads and exact-space/API-key denial. Server-provided task slugs and target
hashes make local code execution optional. The corrected lineage query naturally
uses the existing lineage/predecessor indexes at 10,101 synthetic task rows; one
warm EXPLAIN ANALYZE measures 0.089 ms, without a production latency claim.

Full exact-source Python/browser/native/scan acceptance and independent downloaded
artifact grading remain required in the focused PR; unchecked items are not acceptance.
M3–M6 remain unstarted. Production quality, corpus coverage, cost and scheduled
execution cannot be inferred from deterministic synthetic tests.

## Boundaries and reuse

Keep the six SQL coordination tables, schema0036, operation catalog, consumer
lock and registered app identities. No new server model engine or scheduler.
The external `c0-compile` executable ships in the independent ingestion/client
package. It uses the existing MCP authentication/account checks and installed
Core external helpers (`navigation_plan`, `compile_plan`, `verify_pending`) and
calendar. It uses the helpers already released in Core0.42; the optional semantic reservation
requires the actual new server input. Producer
validation is explicit and does not claim an unpublished release is installable.

One bounded invocation reads policy/current state, claims an existing compiler
run, discovers current originals, reserves and observes external model calls,
validates plans, applies only automatically supported changes, reads back targets
and originals, and records complete/partial status. Queue-only, contradictory,
uncertain and ambiguous duplicate decisions remain held. Source instructions are
data. The model receives allowlisted read tools and no credential, shell, policy,
project configuration, ingestion or direct Wiki mutation tool. Model requests
have bounded input/output, request count, elapsed time and server reservations.
No model/tool response text is printed or persisted in the local journal.

Private atomic journals contain bindings, opaque request/run/task identities,
request fingerprints, usage and outcome metadata. Persist intent before I/O.
An interrupted model invocation or uncertain write blocks automatic retry until
its saved C0/provider state is reconciled. Local flock prevents overlapping
processes; server fences and budgets remain authoritative across hosts.
Authentication failure never falls back to another account, space or OAuth flow.
API keys come from private files or systemd credentials, never command arguments.

Use existing project daily/weekly host work when configured. Project compilation
requires its existing active project lease; the runner must not install a second
project scheduler or claim ordinary-space maintenance in a configured project.
Ordinary-space schedules explicitly bind policy timezone and local times.
Calendar occurrence keys coalesce missed ticks, use the existing first-fold/gap
algorithm and retain incomplete work without resetting C0 budgets. A configuration
change stops unattended work pending explicit local configuration review.

## UI and package contract

The reader-only Use with AI page supplies eight copyable prompts in English and
Italian: compile, bootstrap, retrieval feedback, daily, weekly, ChatGPT scheduling,
external scheduling and status/recovery. Bind exact authorized selected space,
account, connection, actual current capabilities, policy revision and project
manifest/schedule where present. No guessing timezone or fallback on access loss.
Readers receive only status guidance; missing compiler capabilities show an
upgrade explanation and ordinary existing workflows remain usable. Clipboard
failure leaves selectable text. Preserve query response and selected-space guards.

Generic, standalone and project archives include one shared scheduling reference,
with closed asset/runtime/native inventories updated together. Installing a
package does not establish connection, permissions or scheduled execution.
ChatGPT instructions discover actual scheduling/connector/skill availability,
reconcile existing tasks and read saved IDs/settings. A host that cannot execute
with durable authorization is BLOCKED. Observe actual C0 revisions/results rather
than trusting a host's completed flag.

## Refined weekly inference reservation

The real MCP regression exposed an inherited gap: an unchanged source-bound
improvement correctly deduplicates to its terminal initial-create task, which
cannot be leased again solely to account for weekly semantic inference. Do not
reopen it, manufacture a task/contradiction, change canonical identity or reset
attempts. Add one alternative input to existing reserve_model checkpoints:
semantic_page_id +1–3 current source_bindings, instead of task_id +task revision.
Only a live ordinary-space weekly selection may use it. Bind the exact selected
current page and original identities; atomically reserve original document/page
and model day/week budgets and reject concurrent unresolved calls for that page.
Saved call metadata contains only the semantic target/bindings and task_id=null.
Reserve/start/replay and semantic review recheck exact selected page/originals.
Returned/failed/reconciled model observations remain accounting, so real usage can
be recorded after evidence changes; they do not authorize a stale semantic review.
Semantic review requires a returned call matching its page and exact bindings.
Task-based reservations and publication usage contracts remain unchanged.

A supported no-change semantic review may complete the selected page. New changes
need a genuine canonical proposal, separate task reservation and actual task
inference through the existing engine; terminal dedup is never overridden. Held
or unsupported findings remain partial. No table, migration, operation, scope or
scheduler is added. Producer Core becomes0.45; released Core0.42 remains the app's
explicit immutable consumer. External basic compilation helpers are available in
released0.42. The runner detects semantic_page_id in actual checkpoint schemas;
older servers retain basic work and report weekly inference unavailable rather
than inventing a usage receipt. Publication and consumer adoption remain separate.


Completed bootstrap stages use successor invocation identities while retaining
all server task attempts, deduplication, source cursors and day/week debits. An
assessment plus three children therefore does not consume four crash attempts on
one run. Only genuine settled/assessed progress permits the next batch; uncertain
writes/model calls retain their original identity and block rotation. Daily/weekly
occurrence identity remains stable. Known returned model receipts can reconcile
only their matching return_model checkpoint, never clear an unrelated pending
write. Lost claims/proposals retain exact metadata/key; publication recovery
independently verifies the actual saved task and preserves intent across another
interruption. Local journals contain no source or generated Wiki body.
